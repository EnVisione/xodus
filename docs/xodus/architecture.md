# Xodus service architecture

## Requirements

- Games downloaded through Xodus retain executable in encrypted form - following in Windows footsteps
- Users shouldn't need to login multiple times - auth confirmations are fine
- Steam games using Microsoft services should be able to use Xodus login
- Users want to use their launcher of preference, not another launcher. Integration should be simple

## Package transaction safety

Package segment paths are untrusted input. Before the streaming or download writer creates any package output, it rejects empty, absolute, drive prefixed, traversal, mixed separator, and Windows invalid or reserved path components. On Linux, output files and intermediate directories are opened relative to the selected root with `openat2` resolution flags that forbid root escape, magic links, and symlinks. A rejected path makes the command fail and must not create a file outside that root.

The Phase 2 XSP parser slice accepts only tables that begin after the fixed 860-byte header, end within the seekable input length, and declare no more than 1,048,576 fixed-size records. It rejects new-data and copy-data block ranges whose start plus count overflows before returning any entry. It uses a checked record-count conversion and a fallible exact reservation after the count cap, returning a typed I/O failure instead of aborting on allocation. It returns typed header, record, I/O, count, offset, overflow, and bounds errors before writing a filesystem path. Synthetic in-memory tests cover valid and rollback descriptors plus invalid-magic, invalid-record, truncated, interrupted-recovery, oversized-count, before-header-offset, and new-data or copy-data range-overflow cases. The credential-free XSP apply command rejects truncated and trailing new-data payloads before a byte apply can return a result, and the stream helper reports trailing payload bytes to the transaction layer. It also rejects the interrupted recovery descriptor before staging and preserves an existing destination file.

The credential-free CLI `apply-xsp` command consumes a local descriptor, base image, new-data stream, and explicit truncated SHA-256 source and target hash manifests. The manifests are bounded before decoding, and their hash entry vectors reserve fallibly from the bounded text size so malformed or memory-constrained input returns an error instead of aborting. It validates the descriptor and hashes, rejects target output larger than available space, acquires the destination lock, recovers interrupted transactions, rechecks destination capacity after recovery, and requires the XSP declared disk space plus a checked twenty percent reserve before creating a staging transaction. It then streams the bounded update into the journaled staging directory, synchronizes the staged output, and promotes it atomically. Its synthetic integration tests apply a valid forward update, replace an existing active file through rollback, attempt a target-hash-mismatched replacement, recover a process crash after staged output, and run after an MSIXVC2 base-to-update replacement in the same destination, proving that the active output remains unchanged and no staging transaction is left behind. This proves a local synthetic XSP transaction, but it does not substitute for an authorized retail source-to-target update.

The streaming CLI races its package reader and transaction worker against `Ctrl+C`. Cancellation returns a nonzero status and drops the in-flight operation before promotion, so the journaled staging directory is owned by the transaction guard and the last verified destination remains the active state. The cancellation wrapper has a deterministic test proving that the operation is dropped before promotion; it does not claim a real package lifecycle or target-game result.

XSP update preflight now validates the active content identity and source version, forward versus rollback version direction, expected source block hashes, target range ordering and bounds, copy source bounds, target hash coverage, target output size, and available disk space before a transaction can be considered eligible. The CLI measures free space after destination locking and interrupted-transaction recovery, and its checked twenty percent reserve rejects storage exhaustion or reserve arithmetic overflow before staging. When the base input is large enough to be an XVD, the CLI reads its bounded 4 KiB header before staging and requires its content identity and package version to match the XSP source. Small non-XVD inputs remain available for credential-free synthetic fixtures. A bounded in-memory apply helper copies new-data and copy-data records into a new buffer and verifies truncated SHA-256 block hashes without mutating the source image. It reserves the bounded output buffer fallibly and returns a typed allocation failure under memory pressure. A separate bounded async stream helper verifies every source block before writing, applies copy and new-data records one block at a time, verifies every target block, rejects trailing new-data bytes, and limits its working buffer to 64 MiB. It reserves the block buffer fallibly before any source read. Direct synthetic stream tests cover both forward and rollback application with source and target hashes, plus truncated-source, truncated-new-data, trailing-new-data, and target-mismatch rejection. The stream helper writes to a caller-owned staging output, while atomic promotion and crash recovery remain the transaction layer's responsibility. The in-memory helper refuses outputs larger than 64 MiB, so neither helper alone proves a real title update. The reviewed XSP fixture also has a deterministic 256-mutation regression that asserts asynchronous parsing never panics on malformed bytes.

Display catalog lookup builds its endpoint through the URL API. Product identifiers are path segments, while market and language values are query parameters, so delimiters cannot alter the request target. The endpoint base does not carry a trailing separator before the product segment is appended, avoiding an empty path segment and the resulting catalog 404. Empty, control-bearing, oversized, and excessive language inputs fail with a typed error before authentication or network activity. The response body remains bounded before JSON decoding.

The MSIXVC2 boundary inspector reads ZIP central-directory metadata without extracting package files. It rejects excessive entry counts, duplicate or unsafe paths, symbolic links, unsupported compression methods, missing required metadata, and oversized metadata entries. Entry indexes and metadata collections use fallible reservations after the entry-count cap, so malformed or memory-constrained inputs return typed failures instead of aborting allocation. The bounded visitor validates that structure before rewinding, exposes each safe entry to a caller-owned sink, and drains every entry through the ZIP CRC checker under a caller-supplied uncompressed-size limit, so callers cannot bypass the path and metadata boundary by invoking verification or visiting entries directly. A deterministic mutation regression exercises the bounded inspector against 256 byte-level mutations of the reviewed fixture and asserts that malformed input returns a result rather than panicking. The offline CLI `inspect` command exposes the metadata check without initializing device credentials. The offline CLI `install-msixvc2` command now checks destination capacity for the bounded uncompressed archive plus a 20 percent reserve, extracts a validated local archive into a bounded staging transaction, synchronizes each file, and promotes the complete set under the destination lock; archive path indexes, stale path indexes, and staged specification collections use fallible reservations, and synthetic integration tests install a base fixture, apply an update fixture, reject an integrity-mismatched replacement, and recover a process crash after staged extraction while preserving the active state. This proves safe fixture installation and replacement recovery, but it does not yet install, decrypt, or execute retail encrypted MSIXVC2 content.

The XVD parser returns a typed I/O failure when a metadata-directed seek to XVC information fails. It rejects XVC information versions above 2 with a typed error before reading region headers, preserves the existing version 0 no-region behavior, and rejects an XVC region count above 4,096 before it reads region headers or reserves their vector. After the count cap, the region-header and encrypted-section vectors reserve fallibly with typed allocation failures. It rejects an unsupported encrypted XVC key ID with a typed error rather than aborting, rejects an encrypted region offset below the computed user-data base before subtraction, checks encrypted-region end arithmetic before page calculation, and uses checked page-count conversion with fallible reservations for encrypted-region data units and hashes. Package-file parsing now validates the fixed user-data header against the declared user-data extent before seeking or reading, and rejects a package header length smaller than that fixed header before reading package metadata. Segment-metadata parsing applies the same preflight to its fixed header and rejects a declared header length smaller than the fixed 100-byte structure before reading the segment table. Package-file table extent validation and each entry-cursor advance also use checked arithmetic with typed failures before metadata-directed reads. The package-file and segment-file maps use fallible reservations before insertion, segment path buffers reserve fallibly from their declared UTF-16 length before reading, copied segment hash slices reserve fallibly before cloning, and duplicate segment paths are rejected before map growth, so package-influenced metadata cannot overwrite an earlier file or reach an infallible path or hash-vector allocation. These paths return typed allocation and duplicate-path failures rather than aborting on memory pressure or silently changing file selection. Its regression tests use only in-memory synthetic XVD headers and metadata, including a reader that fails the seek, an unsupported information version, an oversized region-count layout, supported and unsupported key-ID layouts, a below-base region offset, an overflowing region end, an unreservable maximal region length, short fixed headers, short declared header lengths, and a package-table cursor overflow. They prove propagation and bounded region parsing without inspecting a package or mutating the filesystem. The XVD virtual stream also validates its current cursor against the virtual extent, bounds each read by the remaining extent, rejects overreported counts, and verifies the post-read cursor before returning success.

NTFS stream layout inspection now reserves report, filtered-report, and nonresident data-run vectors fallibly before insertion. Attribute-list synthesis uses a fixed 4,096 byte temporary buffer cap with fallible reservation, so the filesystem-reported cluster size cannot turn metadata inspection into an unbounded allocation. Data-run merging checks start and length additions before mutation and returns typed invalid-data failures on overflow. Deterministic tests cover contiguous merging and both overflow paths. These checks bound metadata inspection only; they do not claim a retail package or runtime lifecycle result.

XVD header layout arithmetic is calculated once through a checked layout object before any metadata-directed seek. Page-to-byte conversion, metadata and hashed-page accumulation, hash-tree depth, resilient page counts, and each derived offset return typed arithmetic failures. Hash-tree block lookup also rejects unsupported XVD types, invalid levels, depth underflow, and checked result overflow. An adversarial maximum drive-size header is rejected before the XVC information seek, and valid sector conversions retain their normal values.

The HTTP reader validates pending chunk offsets before slicing, uses checked arithmetic for logical and active stream positions, requires an active response cursor to match the logical cursor before polling for more data, rejects received data beyond the declared response extent or total length, and requires resumed responses to preserve the requested start and original total length. Partial responses must also report a content length matching the inclusive content range. Direct reader tests cover complete initial responses, short-response resume, resumed content-length mismatch, cursor drift before polling, corrupt pending offsets before slicing, partial pending-chunk cursor continuity, pending-offset addition overflow, total-length drift, overlong response extents, and logical or active-position addition overflow. Transport failures, request timeout, too early, rate limit, and server status responses plus short streams consume a three-attempt reader-wide retry budget, while permanent client statuses and invalid range or extent failures return immediately; exhaustion returns a typed retry or premature-EOF error. These checks return typed errors before the reader exposes an invalid position or extent.

The prefix cache applies the same declared-length boundary to local cache reads and upstream chunks. Cache positions, pending chunk offsets, cache write positions, and cached length advance through checked conversions and additions. The requested prefix target end derives from the remaining declared length without unchecked `usize` to `u64` conversion or saturating overflow. An upstream reader that supplies more bytes than the declared remote length is rejected before those bytes are written to the cache, and a cache read that would move beyond the declared length returns a typed invalid-data error. Deterministic tests cover a maximum bounded target, a position beyond the declared length, and cache-position addition overflow.

The XVD HTTP download path requires partial-content responses with an exact inclusive Content-Range, a stable total length across reconnects, and a matching Content-Length before activating a stream. Transport failures, timeouts, empty chunks, short streams, request timeout, too early, rate limit, and server status responses use one bounded download-wide retry budget; permanent client statuses and invalid range, total, and length metadata fail immediately. Received body bytes cannot exceed the aligned page span, and retry exhaustion returns a typed error before output promotion. Local extraction and download output writes retry only transient, interrupted, timed-out, would-block, or other transport-style errors; deterministic output-writer tests prove transient failures retry through success while permission and invalid-input failures return immediately. Direct extraction tests now exercise a full synthetic page through `extract_file`, prove the page hash is checked before output, and prove transient output failures retry through a successful extraction. Direct HTTP download tests serve bounded local partial responses, verify the requested range, retry a transient server status before promotion, promote one verified byte, and reject a page hash mismatch before output.

The HTTP reader's pending-chunk, logical-position, active-offset, and response-extent helpers now include a deterministic seeded property sweep over 4,096 bounded inputs. Each generated case proves that valid extents preserve their checked sum and that overlong or mismatched extents return `InvalidData` without relying on a network response.

When a segment carries data-integrity hashes, both HTTP download and local extraction verify the complete encrypted 4 KiB page against the first 20 bytes of its SHA-256 digest before decryption or output writes. Missing hash entries and mismatches return typed errors, so an unverified page cannot be promoted. Segments without an integrity table retain the format's explicit no-hash behavior.

The shared binary parser now builds nested generic-array chunk references through checked slice bounds instead of an unsafe layout transmute. The layout invariant is that `GenericArray` stores contiguous elements with the alignment of its element type, so each borrowed chunk remains a complete aligned view of the original array. Nested-array and aligned-element regressions prove chunk size, alignment, order, and round-trip values while keeping the type-level reader extent contract.

CLEP challenge reshaping is isolated to `clep_obfuscate` and `clep_deobfuscate`. The packed `ClepV2` and `ClepV4` layouts are each exactly 2,048 bytes with byte alignment, matching the fixed byte-array buffer. Runtime block traversal uses checked `as_chunks_mut` slices rather than a mutable layout transmute. Explicit size and alignment assertions plus the obfuscation round-trip test protect that invariant.

Xbox package authentication now propagates token, exchange, HTTP status, JSON schema, unsupported-response, empty-collection, response-body allocation, and missing-user-claim failures as explicit errors. Auth header construction also rejects empty XSTS tokens and user hashes. The shared JSON request path rejects non-success status before decoding, reserves each bounded response chunk fallibly, and returns decode failures for incomplete responses. It no longer panics on a malformed or incomplete service response before package metadata access, and regression tests cover HTTP status, schema, and empty-claim failure handling.

Authenticated package metadata is validated against the requested content and optional version identifiers before callers can select files or construct CDN URLs. The response must be marked as found, carry bounded nonempty package identity and version values, contain at least one file, keep every file's content and version identities aligned with the response, and contain no duplicate file names. Negative file sizes, empty file names, malformed or wrong-length nonempty file hashes, empty delta identifiers, missing CDN roots, unsafe CDN roots, and unsafe relative URLs fail with typed invalid-data errors before downstream download or streaming work. Empty file hashes remain valid for service responses that omit a digest. Both latest and exact-version package retrieval paths use the same validation boundary.

Catalog subproduct discovery parses entitlement keys without allocating a temporary split vector. It accepts only the existing three-part `big` shape and reserves each collected subproduct fallibly, so a bounded but memory-constrained catalog response returns an error instead of aborting while preserving the existing redirect-cycle and depth limits.

SOAP passport token conversion now returns typed failures for missing encrypted legacy data, missing compact binary data, unsupported token types, and legacy serialization errors. Device, Xbox, refresh, login, and license callers propagate or report these failures before storing or using a token. Silent refresh also fails closed when persisting the refreshed STS token fails, so a successful exchange cannot hide a broken persistent session. Empty refresh collections also fail explicitly instead of indexing an absent response.

Device and user token exchange now validates the stored binary secret before constructing the fixed-size signing state. Missing, undecodable, and non-4096-byte secrets return typed RST failures before signing or network activity. The service path also reports missing device state and unsupported or empty exchange responses instead of panicking or using a placeholder.

Device credential provisioning now propagates request serialization, HTTP status, transport, response-body allocation, response-body, and XML deserialization failures. Its bounded response reader reserves each chunk fallibly before appending. Provisioning stops without persisting a partial device record, and callers receive a failure instead of continuing with missing or corrupted credential state.

Live RST responses enforce their declared body limit before XML parsing and reserve each streamed chunk fallibly. The completed response is converted into its owned UTF 8 string without a second body-sized clone. The derived key token index reserves its response sized map and each copied identifier and nonce fallibly before signature verification or SOAP decryption. Allocation failure is reported as a typed response error, while oversized content remains a distinct limit failure.

The BCrypt RSA private-key parser now validates magic, component extents, prime factors, modular inversion, and RSA construction through typed errors. Malformed persisted key blocks are rejected before slicing or signing, and device reauthentication returns the failure so the CLI and service cannot report or continue a false-success startup.

Live RST RSA signing uses the AWS-LC provider through bergshamra and kryptering on Linux. Non-Linux targets select the RustCrypto provider so the same signing path remains buildable on macOS and other supported platforms where kryptering does not expose AWS-LC. The BCrypt parser emits a bounded PKCS#8 DER representation containing the validated RSA components instead of constructing a direct RustCrypto RSA key, and the DER bytes are held in zeroizing storage until signing completes. The parser validates the modulus, private exponent, CRT coefficient, and DER length arithmetic before the key reaches the signing provider. `deny.toml` records the dependency license and source policy plus the reviewed GTK3 advisory exceptions.

The all-target dependency audit still reports `rsa` 0.9.10 with `RUSTSEC-2023-0071`, the Marvin timing side channel, and the advisory has no fixed upstream release. The actual CachyOS Linux graph, checked with `cargo tree --workspace --target x86_64-unknown-linux-gnu -e features -i rsa@0.9.10`, contains no `rsa` package because the Linux build selects the AWS-LC provider. The vulnerable package remains in the lockfile for non-Linux RustCrypto feature builds. The service boundary limits direct invocation to a mode 600 Unix socket and the owning user ID, so an unauthenticated remote client cannot directly reach the signer. Issue 13 tracks removal or isolation of the non-Linux RustCrypto path before shipping those targets; it is not evidence of `rsa` in the CachyOS Linux binary.

The MSIXVC2 install path has a synthetic update regression that installs the base fixture, promotes the update fixture into the same destination, removes the stale base package entry, and preserves the required package metadata without credentials or network access. A combined CLI regression now runs that package replacement before a valid XSP update and a failed XSP replacement, proving both package state preservation and transaction cleanup across the two local format paths. Direct package download retry coverage now also proves that a short transfer leaves an existing verified package in place and removes the failed staging transaction before a later complete response is promoted. The service IPC boundary now enforces a 60 KiB payload limit before allocation, rejects unknown message types instead of defaulting them, caps active connections, limits each connection to 120 messages per minute, applies 30 second deadlines to message reads and writes, and cancels both waits immediately when service shutdown begins. The legacy package download command now rejects missing CDN roots, malformed or non-HTTPS CDN URLs, credential-bearing URLs, and invalid sizes, tries each distinct validated CDN root within one bounded three-retry budget, retries only transport, request-timeout, too-early, truncated-body, server, and rate-limit failures, checks HTTP status and declared and received byte counts, validates a supplied base64 SHA-256 `FileHash` while streaming, stages output beneath the journaled transaction directory, synchronizes it, and promotes it only after the complete response and optional hash check succeed. Bounded local tests prove the transient status policy, short transfers, complete hash mismatches, and a process crash after a partial staged body preserve an existing verified package and leave no staging transaction after recovery. A failed attempt is discarded before the next bounded request, so partial output cannot be promoted or retained as a successful package. Output creation, stream, sync, and promotion errors return failure instead of reporting success after a partial operation or panicking on service data.

The same command accepts an optional `--version-id` and retrieves an exact package revision through the packages service `GetSpecificBasePackage/{content_id}/{version_id}` route. Both content and version identifiers are added as URL path segments rather than concatenated into a raw URL, and empty, control-bearing, or oversized identifiers fail before authentication or network activity. Package download candidates are built by joining validated relative paths to bounded HTTPS directory roots. Roots with credentials, query or fragment components, non-directory paths, raw dot segments, or encoded path escapes fail before a request, and relative paths cannot escape through absolute, ambiguous, dot, encoded dot or separator, query, fragment, control, or oversized components. Direct package downloads check the destination filesystem before issuing a request. The required file size is expanded with checked arithmetic to include a twenty percent reserve, and insufficient capacity returns a storage error before any staging transaction or network body is created. This check is per file, so each sequential download retains the reserve for its own staged write.

Direct downloads convert each package file size to an unsigned value before constructing CDN URLs or entering the dry run path. Negative metadata therefore fails before URL output, network activity, staging, or capacity arithmetic.

The remote `streaming` command accepts the same selector, so a recorded source `VersionId` can feed the existing range-checked MSIXVC reader and transaction path. Remote streaming checks destination capacity for the package cache before creating a transaction, then checks capacity again for changed segment files after local state comparison. The download command can optionally write a package revision manifest with `--manifest PATH` after all selected files have completed and been promoted. Completed segment files and the package cache are synchronized before promotion. Each streaming run writes the cache and changed sidecars beneath a unique transaction directory, records staged, backup-pending, backed-up, promoted, and rollback-safe removal states in a synchronized journal, and promotes them only after all extraction or download work succeeds. The backup-pending state is journaled before retiring an existing file, so recovery can distinguish a crash before the rename from one after it and preserve the last verified file in either case. Journal updates are written to a synchronized temporary file and atomically renamed into place, so a crash during journal serialization leaves either the previous valid journal or no new transaction state rather than a truncated recovery record. Journal decoding reserves its bounded byte buffer fallibly before reading and reserves parsed entries and path indexes fallibly before validation. A per-destination lock prevents concurrent mutation while independent destination roots remain operable. The lock is opened relative to a validated root descriptor with `openat2` and the same beneath, no magic link, and no symlink resolution policy as package files, so a hostile lock symlink cannot redirect mutation or locking outside the selected root. Existing package files are backed up before replacement, stale local sidecars absent from the remote manifest are removed through the same transaction, and a failed promotion or a discovered interrupted transaction restores the prior files. Promotion entry and path indexes use checked counts and fallible reservations before they are populated, so a remotely influenced or overflowing transaction list returns a typed failure instead of wrapping capacity arithmetic or aborting allocation. Deterministic in-process and process-level crash coverage kills a disposable subprocess before backup, after backup rename, after backup journaling, after staged rename, and after promotion journaling, then proves recovery restores the prior package state and removes the unverified new file. Remote page hashes are preserved through job construction so nonempty hash tables reach the downloader and extractor. Full update workflow coverage remains Phase 2 work.

Promotion and rollback now synchronize the parent directories after backup renames, staged-to-final renames, and restored or removed files. Package roots are opened from the current directory with no-magic-link and no-symlink resolution before any package or journal entry is accessed. These moves and removals use validated parent directory descriptors with beneath and no-symlink resolution, so a staged symlink or a replaced final parent cannot redirect a transaction outside its selected roots. Restore validates that a recorded backup is a regular file before touching the active path, so a missing or invalid backup cannot delete the last verified file. If directory synchronization fails after a rename, the journal state retains enough information for rollback to restore the prior verified file rather than silently discarding it.

Real package integrity coverage, the full rollback policy, and complete update workflow coverage remain Phase 2 work. The account backed Xbox Live development token test is not part of ordinary offline verification and currently requires an explicit bounded opt in.
