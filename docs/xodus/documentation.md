# Xodus package libraries

The `msixvc-common` library parses a Package Resource Index through `resources::pri::Pri`. The input stream is limited to 16 MiB. Hierarchical names and paths have additional limits to bound memory and traversal. Malformed or oversized data returns a parsing error. Resource lookup and qualifier explanations operate on the parsed index.

The `msixvc` library exposes page and byte types, a hash tree stream, and an XVD layout view. `XvdHeader::layout` validates the existing checked header layout before constructing the view. It rejects unsupported integrity-disabled or resilient layouts and page counts outside the supported range. The hash tree stream checks the supplied hash count before reading, compares the 20-byte digest portion of each parent entry without treating its four-byte unit as hash data, and terminates on read or integrity errors without exposing entries from a failed page.

The streaming prefix cache waits for each pending write before exposing cached bytes. It supports seeking back into the cached prefix and resuming a later read after a cancelled cache operation.

Streaming selects a missing or wrong-sized installed file for extraction even when cached package metadata matches. Encrypted files are sized in full pages for this check and for the staged-space estimate. When an encrypted file has matching metadata and size, its pages are compared with the package's page hashes before it can be skipped; these hashes are not yet authenticated by the streaming command. Matching metadata and size do not prove that decrypted installed bytes are intact, so same-sized corruption in those files may still be skipped. On Linux, workers reading a local source reopen the already-open file through its retained descriptor, so replacing its pathname does not switch the source. Concurrent changes to the same underlying file are not prevented.

The CLI and service reject insecure redirect destinations before sending a follow-up request. HTTPS redirects cannot downgrade to HTTP, and HTTP redirects are limited to local loopback fixtures. Library callers supplying their own HTTP client must apply `xodus::api::secure_redirect_policy` or an equivalent policy; checking the final response alone does not prevent an unsafe redirect request.

The `PinnedXvdKey` library type checks an RSA public key blob against a SHA-256 fingerprint and verifies the first XVD page using RSA-PSS with SHA-256. `from_microsoft_retail_blob` applies the retail gaming-key fingerprint; `from_bcrypt_blob` accepts another fingerprint that the caller must obtain independently. `XvdFile::parse_with_verified_header` checks the exact header bytes before parsing them, but does not authenticate later metadata or payload pages. `AuthenticatedXvd` additionally binds the signed header to an expected content ID, package ID and version, authenticates each hash-tree level, and returns data pages only after their hashes match. Its cache contains at most four tree pages. `AuthenticatedReader` provides a seekable view for parsers, authenticating header, tree, and data pages before returning their bytes. Embedded XVDs, mutable data and header padding are rejected by that view. It has not yet been integrated into the download or streaming commands.

For package-sized XSP updates, `apply-xsp` requires `--source-package-id` and `--target-package-id`, in addition to the descriptor, source and target block-hash manifests, new data, and block size. The two package IDs must come from an independent source. The Microsoft retail public key is bundled and checked against a pinned fingerprint. An optional `--retail-signing-key` file must contain the same 539-byte BCrypt public-key blob and match that fingerprint. The command authenticates the source before applying the plan using the same open source file, then checks the staged target's signed identity and every hash-tree-covered page before promotion. Each image must end at the signed data extent, with no truncation or appended bytes. A missing, incorrect, unsigned, unsupported or corrupt package fails without promoting the staged output. Embedded XVDs are rejected. The descriptor and supplied block-hash manifests are not themselves publisher-authenticated; they cannot establish target integrity in place of the staged target check. Mutable data and header padding remain outside the signed hash tree and must not be treated as authenticated. The download and streaming commands do not yet use this verifier and do not gain a new transport option from it.

Transaction promotion retains its recovery directory if promotion fails, including when an attempted rollback also fails. Before making new changes, download, install, update, repair, and uninstall operations acquire the transaction lock and attempt recovery. Each restore is journaled before the prior file is moved, allowing recovery to resume after interruption during rollback. An error after commit but during cleanup is reported separately; the completed journal allows cleanup on a later run. New transaction directories contain an ownership marker so recovery can distinguish an interrupted staging directory from an unrelated similarly named directory. Unrecognized unjournaled directories and unmarked completed directories are left untouched and reported. Legacy unfinished journals remain readable. Package paths may not use reserved transaction or ownership names.

The MSIXVC2 commands stage, restore, and remove archive members; they do not install a playable game or authenticate a retail publisher signature. A transactionally updated ownership record identifies paths that can be replaced or removed, including when the files at those paths were locally modified. The record is not signed and assumes the destination is protected from untrusted local writers. Unrelated files at other paths are preserved, including files inside package directories. Older staged files without an ownership record are not automatically claimed or removed; an operation that would overwrite unowned files fails rather than guessing. To adopt an older staging directory, use `install-msixvc2` with its matching archive and `--adopt-existing`. Xodus verifies every existing matching path byte for byte before claiming it; a mismatch stops without overwriting the file. Files not listed by that archive are left unclaimed. The local EAppx extraction command is not available. The upstream extractor needs path containment, integrity, protected executable handling, and transactional output before it can be safely exposed here.

Xbox user authentication accepts newer compact encrypted delegation tickets by selecting the ticket prefix expected by the Xbox user authentication endpoint. Opaque and signed-only tickets retain their existing representation, and the stored session and other service endpoints are unchanged.
